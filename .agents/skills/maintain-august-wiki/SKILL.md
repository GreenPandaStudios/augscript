# Maintain the August wiki

Use the repository's `docs` as the canonical published documentation. Read `docs/writing-docs.md` for editorial decisions and `docs/maintaining-docs.md` for the source-to-guide mapping and generation workflow. Read `docs/research/wiki-editorial-design.md` when changing the information architecture or writing style.

Route by reader need: a sequential lesson in Learn, a task in Guides, a precise contract in Reference, rationale/evidence under About, or a repository process under Contribute. Preserve useful URLs and anchors. Write connected developer prose; use lists for actual sequences and tables for comparisons.

For a behavior change, identify the affected public contract from source and regression tests, then update its handwritten guide in the same change. Update Javadoc and `src/help.ts` when their observable contracts change. Keep readiness, roadmap, and gap claims tied to implemented and approved scope. Do not expand an ordinary docs change into language design or security-policy changes.

For lessons, state prerequisites, file locations, actions, and expected output. Complete `aug` fences need `project` and `file` metadata plus `docs/examples.json` expectations. Label fragments and intentional failures. Verify important failure demonstrations against the checker. Nested handwritten pages are included in the executable documentation test.

Start application onboarding by installing the published CLI once (`npm install --global @greenpandastudios/aug-cli@next`), then use `aug init NAME`, enter the project, and use `aug run`. Keep `npx` as an optional alternative. Verify installation against the release being documented. Reader workflows must use published tools and downloadable example projects; do not require cloning the language repository or invoking its internal CLI. Keep source-workspace commands in contributor guides. On qualified LLVM targets, run obtains pinned compiler/runtime and package artifacts without a separately installed native toolchain. C reference builds and native package authoring require their stated maintainer tools. Do not claim that init prepares dependencies. Clearly label pending release instructions and recheck installation instructions when distribution changes.

Use the two published `aug-build` and `aug-runtime` bases for Docker deployment; Dev Containers select the build image directly. Keep their tags aligned with the published CLI version, prepared compiler artifact cache and relocatable deployment bundle. Copy the executable with its neighboring `lib` and `share` directories. Ensure cache paths are writable by the container user. Follow the container verification notes in `docs/maintaining-docs.md`; distinguish tested native execution from editor installation, forwarding, and host mount behavior.

Generated API, construct, gallery, and adjacent spec files belong to their generators. Edit declarations, Javadoc, help, catalog, or generator inputs; run `npm run docs:generate` and commit the resulting artifacts. Keep indentation/braces views and dependency links intact. Preserve the reading path from project overview through module/class interactions and API sequences to the compiled explanation and exact source. Diagrams are deterministic static views of checked code; keep callbacks, interface dispatch and foreign internals explicit as boundaries. Use generated Mermaid rendered as SVG, with readable small and large views. Tie availability claims to the published compiler version. Do not edit `dist` or `vscode/compiler`.

Before delivery, run `npm run check`, relevant regressions including `node --test tests/documentation.test.mjs`, `npm run docs:check`, and `npm run docs:build`. Run gallery regressions if its generation changes; run installed-package tests for distribution changes as required by `AGENTS.md`. Inspect a rendered page at narrow and wide sizes when changing layout or navigation. Report exact checks and remaining limits.

Source research from official documentation, source code, original papers, or standards. Cite factual claims nearby, distinguish synthesis from evidence, and avoid copying another site's prose. Benchmark and agent-productivity claims require reproducible, scoped evidence; do not turn design intentions into guarantees.

For package changes, test a public Git URL and an installed CLI. Keep optional library examples on ordinary source imports; do not introduce legacy builtin aliases. Explain export.aug, aliases, exact commit locks, and sharing a tag before registry metadata. Include AGENTS.md and request files in downloadable starters. Confirm the release containing a command exists before describing it as available through npm.

For a prose audit, read every handwritten page and representative generated pages in context before editing. Rewrite paragraphs around the reader’s task; a banned-word replacement is not an editorial pass. Check neighboring sections for repeated introductions and warnings. Read each changed explanation aloud during the editorial review. Remove signature-description filler, repeated inference announcements, generic promises, and local-machine narratives from reader guides. Keep concrete limits and evidence. API signatures must include checked results and errors even when source inference omitted them. Prose checks catch specific recurring phrases; they do not measure whether writing is human.
