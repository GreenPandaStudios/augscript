# Evidence for an August amendment for reliable coding agents

Research date: 2026-09-30. This note informs a proposed amendment; it does not implement language or tool changes. Primary sources were inspected alongside the current compiler. No model was run. Existing ownership, GC, worker/channel behavior, and security policies are outside the proposed scope, including work previously blocked by approval review.

## Finding

The defensible hypothesis is that **a language with checked public boundaries, compiler-selected fresh context, and deterministic edit operations can reduce an agent's avoidable mistakes and the engineer's verification work**. August already supplies much of the first component. The missing work is chiefly more precise compiler tooling and executable requirement evidence. Research supports testing these components; it does not establish that August is the best language for engineering with coding AI.

Do not confuse three claims: a source file is well typed; a change preserves declared boundaries; a change implements the requested business behavior. A compiler can establish the first two within its checked model. The third needs independently meaningful contracts, tests, and review. The compiler's prose description of an incorrect implementation can be perfectly faithful to that implementation.

## Evidence and design implications

### 1. Compiler-selected context and an affected-boundary graph

[RepoCoder](https://arxiv.org/abs/2303.12570) reports improved repository-level completion using iterative retrieval and generation. Its tasks are line, API invocation, and function body completion; this is evidence for retrieving relevant repository information, not proof of safe repository refactoring or an optimal compiler summary format.

[RepoGraph](https://arxiv.org/html/2410.14684v2), sections 3–5, evaluates graph navigation plugged into several engineering frameworks on SWE-bench and studies localization and transfer to CrossCodeEval. It supports graph-assisted navigation as a plausible intervention. Its graph construction and agents differ from August; gains cannot be transferred as an expected August success rate.

[Lost in the Middle](https://aclanthology.org/2024.tacl-1.9/) studies position sensitivity on question answering and key-value retrieval. It motivates measuring information placement and unnecessary context, rather than assuming a larger context allocation solves retrieval. These results do not demonstrate the same effect on every current coding model.

[SCIP's schema](https://github.com/scip-code/scip/blob/main/docs/scip.md) distinguishes occurrences, symbol relationships, and implementation/reference links. This is a useful precedent for method identities and interface relationships. An index provides navigation data; it does not itself prove a behaviorally complete call graph.

**Recommended amendment:** extend `aug context` with a versioned semantic schema and a query rooted at a declaration plus an edit intention. Return exact signatures and boundary facts first, then affected occurrences and selected source. Separate forward dependencies from reverse callers. Include imports/exports, interface implementations, injected dependencies, interceptors, and attached tests as typed edges. For interface dispatch, report a conservative implementation set or an explicit unresolved boundary; foreign implementations must remain marked as such.

Every result should carry compiler/schema versions, relevant source/configuration/dependency digests, root symbol, checked scope, query options, ordering rule, and enumerated omissions. Distinguish **checked scope**, **graph coverage**, and **budget truncation**. `checked` must never imply that every relevant node fit into the request. Prefer root-relative reproducible paths, with package identities and versions; do not include machine-specific paths in portable artifacts.

Budgeting should select complete records rather than cut signatures. Reserve space for a small mandatory boundary summary and omitted IDs with retrieval continuations. A token budget requires an explicitly selected tokenizer; report actual serialized bytes/characters separately. The engineer or model must be able to fetch an omitted source unit. This adds schema and graph maintenance cost, but avoids silently dropping a caller because a full implementation consumed the budget.

### 2. Deterministic refactoring and model-generated behavior

[Clang's refactoring engine](https://clang.llvm.org/docs/RefactoringEngine.html) describes rules with explicit requirements and source replacement results, including operations across translation units. It establishes that compiler-driven transformations are a practical architecture. It is not evidence that every generated transformation preserves semantics, or that a compiler can infer a newly required business argument.

**Recommended amendment:** start with transformations having a narrow, reviewable meaning: symbol rename, input-label rename, and import/export updates for a selected declaration. Use resolved occurrences rather than matching strings. Return an edit plan containing old revision/digests, affected files, replacements, diagnostics, and public-contract deltas. Apply against exactly those inputs in a temporary checked workspace; reject stale plans, collisions, overlapping edits, or unresolved boundaries before changing project sources. A failed plan must leave sources unchanged. Check the complete production project and tests before accepting the transaction.

Adding an input, capability, or error is more difficult. The tool may enumerate every site needing a decision and mechanically insert explicitly provided expressions/contracts. It must not guess a default, broaden `unless` to `Error`, or manufacture recovery branches. Propagating a new error may intentionally change a public API; present that delta as part of the plan. A compile-successful transformation is still subject to behavior tests.

This keeps the model responsible for selecting the intended behavior and writing unfamiliar logic, while the compiler performs mechanical occurrence edits. It reduces generated tokens and missed labels but introduces transaction, graph soundness, and formatting requirements. Begin with rename correctness before ambitious automated API migrations.

### 3. Checked boundaries are useful, but not unique to August

[Koka's official book](https://koka-lang.github.io/koka/doc/book.html), sections 2.1 and 3.3, shows effects in function types, including exceptions, console operations, nondeterminism, and divergence. It supports explicit machine-checked effect information as an established language technique. August's current effect model should be described on its own terms: an August pure header is not equivalent to Koka's mathematically total effect.

**Recommended amendment:** preserve August's explicit public capability, mutation, and failure boundaries; make inferred versus declared facts and their source locations visible in context and edit plans. Add a reviewable public-surface delta for widened `uses`, `changes`, and `unless`. Keep broad-error and discarded-error lint policy visible. Do not turn inference convenience into silent public contract widening.

No cited study isolates the effect of August's checked headers on agent success. The hypothesis is that compiler feedback can reject unauthorized effects and incomplete propagation earlier. The measurable benefit is rejected defect classes and reduced repair/review effort, not a promise that checked code is correct.

### 4. Executable requirements before ambitious proof features

[Dafny's reference](https://dafny.org/latest/DafnyRef/DafnyRef), sections 7.1.1–7.1.3 and 11.1, defines preconditions checked at callers, postconditions, write frames, and a verifier. Its treatment of external declarations makes trusted assumptions explicit. This establishes a design vocabulary; adding similarly named August clauses without a verifier would not provide Dafny's guarantees.

[Hypothesis settings](https://hypothesis.readthedocs.io/en/latest/settings.html) documents bounded example counts, deterministic settings and shrinking phases. [Its replay guide](https://hypothesis.readthedocs.io/en/latest/tutorial/replaying-failures.html) recommends retaining explicit examples for permanent regressions because stored or encoded failures can become invalid across versions. [Stateful testing](https://hypothesis.readthedocs.io/en/latest/stateful.html) demonstrates generating sequences of operations against a simpler model.

**Recommended amendment:** add a bounded property-test facility before adopting general static contracts. Define typed, pure generators, deterministic seed and generator-version metadata, case/size/time limits, shrink rules, and replayable concrete inputs. Use explicit capability adapters for stateful tests. Validate generator feasibility and report discarded cases; an impossible precondition must not yield a passing property. Store minimized failures as ordinary checked examples. Finite generation provides counterexample evidence, not universal proof.

For the refund fixture, independently authored properties should cover conservation/bounds, exact replay idempotency, conflict behavior, and dry-run receipts/state. Crucially, combine dimensions: cached versus new request, matching versus conflicting payload, and dry-run versus applied mode. The reviewed bug existed at an interaction of these dimensions.

If production contracts are later added, specify purity, evaluation order, failure behavior, normal versus error exits, bounded immutable `old` snapshots, and build-mode behavior first. Type-checked expressions, runtime-enforced clauses, finite property tests, and statically proven clauses need distinct status in compiler context. Restrict initial contracts to cheap immutable values; do not change ownership, collection, concurrency, or security semantics to implement snapshots.

### 5. Familiarity and sample efficiency need direct measurement

[MultiPL-E](https://arxiv.org/abs/2208.08227) translates benchmarks to multiple languages and examines language frequency/features. It supplies a method for comparable function tasks, while translated tasks require care around different semantics and libraries. It does not identify the optimal syntax for a novel language.

[MultiPL-T](https://arxiv.org/html/2308.09895v6) uses tested translations to generate training data for low-resource programming languages and evaluates fine-tuned models. It supports validated training/example corpora as a practical route to improved language competence. Its gains come from training interventions, not evidence that a short primer alone teaches a zero-resource language reliably.

August's [prompting record](../legacy-refunds/PROMPTING.md) is stronger evidence about this checkout than claims about English-like syntax. A taught, staged controller ultimately passed visible tests, hidden cases, native execution and frozen-spec integrity. Earlier attempts failed, runtime context was initially misallocated, orchestration/reasoning changed, and human review exposed an acceptance gap. There is no matched improved TypeScript control or estimated success rate. The successful lineage is not an autonomous single attempt.

**Recommended amendment:** maintain a compact compiler-tested primer, canonical idioms, precise syntax diagnostics, and valid signature/call exemplars selected from real dependencies. Measure how many examples and repair rounds are needed for new syntax. Familiar-looking wording may still trigger an incorrect Python/TypeScript analogy. Avoid assuming fewer keywords or natural-language headers automatically mean better generation.

## Tests that can falsify the design

These are proposed experiments, not results. First use deterministic fixture tests to establish compiler/tool invariants; model tests then measure their usefulness.

1. **Graph completeness:** fixtures with reexports, generic interface implementations, private helpers, interceptors, injected adapters and startup/test callers. An independently authored expected affected-site set must match the conservative query result. Omitted/unresolved edges must be explicit. Adding an unrelated export should not inflate a used-contract packet.
2. **Freshness and boundaries:** mutate source, dependency version, configuration or a caller after producing context/edit plans. Stale plans must reject with zero source writes. A locally checked view must remain distinguishable from a checked whole production project. Tiny budgets must report omissions without deleting required root contracts.
3. **Transformation invariants:** collision and shadowing cases, same spelling in unrelated declarations, labeled calls, source comments, reexports and interface methods. Rename changes only resolved occurrences; successful plans check; failures leave every file byte-identical. Compare execution before/after for fixed regression fixtures. This is regression evidence, not a general semantic-preservation proof.
4. **Context ablation:** identical models/tasks/settings/budgets with source-only, full `.aug.md`, current `aug context`, and proposed graph context. Hold primer and controller constant. Measure independent acceptance, missed boundaries, source/spec edits, tokens, elapsed time and engineer interventions. Add stale-context and budget/placement controls.
5. **Refactoring ablation:** model text edits versus the same model selecting compiler edit plans, with equal behavior tasks and feedback. Measure exact edit coverage, invalid proposals, accepted incorrect changes and review time. Do not count an unavailable compiler operation as a model failure without reporting it.
6. **Novel-language learning curve:** zero, one and several checked examples; syntax-only, boundary-change and business-behavior tasks; multiple unrelated repositories and model families. Count syntax/import/label failures separately from behavior failures. Include a matched TypeScript workflow and cold trials rather than continuing tuned lineages.
7. **Oracle quality:** seed known dry-run/replay and propagation defects. Compare examples alone with bounded properties/state-machine checks. Require each regression to fail on the defective program and pass on the corrected one; inspect discarded inputs and mutation detection. Keep final acceptance cases unavailable to the generating agent.

Pre-register tasks, intervention boundaries, budgets and primary outcomes. Report all attempts and compiler rejection stages. Use repeated paired trials and uncertainty estimates; clustered tasks from one repository are not independent evidence of broad applicability. Report hidden acceptance and engineer effort separately from compile rate.

## Claim the amendment can responsibly make

“August is designed to make AI-assisted changes easier to inspect and check” describes an engineering objective grounded in implemented boundaries and specs. “The proposed graph/edit/property workflow reduces specific failure classes” remains a hypothesis until the tests above establish it. “Best language for vibe coding as an engineer” has no precise comparator, workload, budget, or human-cost definition; neither this research nor the local prompting lineage supports that superlative.

Prioritize the amendment in this order: precise versioned boundary graph and provenance; compiler-controlled rename plans; replayable bounded properties; then separately evaluated production behavioral contracts. Each can ship with conformance tests and measured limits. None requires silently reopening previously blocked ownership, runtime, worker/channel, or security work.

### Minimal forwarding declaration

Inspection of `parseImport`, `parseExport`, `ImportDecl`/`ExportDecl` and `folderExports` in [`src/parser.ts`](../../src/parser.ts), [`src/ast.ts`](../../src/ast.ts) and [`src/project.ts`](../../src/project.ts) finds no import/export rename syntax. `export Name from file` exposes that same name from a sibling's declarations; importing a name does not make it a sibling declaration available for reexport. Existing ordinary wrapper functions provide runtime forwarding with manually repeated headers. An interceptor's `next()` operates around an existing callable and is not a declaration alias. Neither is equivalent to a signature-inheriting renamed module boundary.

The proposed grammar is `ForwardDecl := "forward" Identifier "to" Identifier End`, preceded by an ordinary explicit import of the target. This is proposed grammar only. `forward` is currently an identifier, so a hard reservation would break programs using that name; use a contextual declaration form or specify a checked migration/version boundary. `to` is already a token. `forward` is a declaration with no body or startup effect, legal in ordinary modules; the existing `export Alias from file` would expose it. `export.aug` should retain its existing exports-only rule.

For an initial amendment, allow only targets proven by the compiler to be imported standalone functions within the prototype's supported pure, managed, non-generic contract subset. Reject cycles, collisions, unresolved/private targets and any alias annotation/body. Do not silently introduce argument remapping, defaults, filtering, recovery, caching, authorization, policies or new effects. Preserve the target's labeled input types and result, exact checked errors and resolved type identities. Represent the alias separately from the canonical target so diagnostics, caller graphs and documentation show both the requested public name and its contract origin. Expansion must use compiler identities rather than guessed imports by spelling.

“Preserves explicit boundaries” must mean the alias has exactly its target's checked public contract, displayed in hover/spec/context and public-contract deltas; it must not infer a new public behavior from an arbitrary wrapper body. A target signature/error change then changes aliases and can make their callers fail checking. Source concision cannot hide that API delta. Effectful forwarding would need a later validated extension preserving canonical capability operation identities, dependency injection, mutation bounds and effective layer errors. The current prototype provides no evidence for that extension. Reject endpoint/native/intercepted targets initially rather than silently choosing whether alias calls apply layers once, twice or bypass them.

A smaller alternative is a **renamed reexport** extension restricted to `export.aug`, if the user need is only a facade's public name. It also requires new grammar/resolution because current exports cannot rename or export imported bindings. Compare that design with a reusable local forwarding declaration before accepting both. Where distinct public names or facade modules are unnecessary, callers can already import the canonical function directly; retaining explicit wrappers plus compiler signature-migration plans is another option with no syntax addition. The fixture shows value for inherited aliases, but does not establish which of these designs gives engineers the best review experience.

The formal amendment can aim to make August outstanding for engineer-guided coding AI by removing mechanical repetition while keeping changed public behavior inspectable. These prototypes justify further compiler conformance work and matched workflow experiments. They do not establish “best language,” general transactional safety, or novel-language sample efficiency.
