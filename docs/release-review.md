# Release validation

A release must validate the language, native runtime, installed packages, editor, and documentation together. This page describes the review requirements; the [release process](releasing.md) supplies the publication commands and platform jobs.

Review source changes against their intended behavior and contributor standards. Resolve findings with concrete regressions where behavior is affected. A review summary names its scope and remaining limitations; it does not claim correctness for code or platforms that were not examined.

Native redistribution review checks each target’s actual dependency closure, retained notices and corresponding source inputs. A notice inventory copied from another platform is insufficient. The Linux C++ runtime recipe backports the upstream aligned-allocation overflow fix and rejects a missing or changed required dynamic export, including its version, binding, visibility and data size, or a newer libc requirement. Its real native regression checks oversized and ordinary aligned allocations, threads, once-only initialization and asynchronous errors. The exact receipt belongs to the sealed artifact being qualified.

The release gates include type checking, language and runtime regressions, LLVM backend parity, sanitizer circuits, clean installed-CLI/native-library consumers, package and extension checks, executable documentation examples, and documentation drift/site checks. Preserve the exact candidate identity and failed reports when a gate rejects a release. Run the repaired candidate through the required gates again.

August 1.0 supports the three hosts in the [platform matrix](compatibility.md). The [tagged preparation run](https://github.com/GreenPandaStudios/augscript/actions/runs/37800823512) retains the exact-source producer, consumer and editor results; the [release](https://github.com/GreenPandaStudios/augscript/releases/tag/v1.0.0) retains the reviewed compiler packs, npm archives, VSIX and checksums. [npm publication](https://github.com/GreenPandaStudios/augscript/actions/runs/37829680524) verifies all four registry archives. The [public-install check](https://greenpandastudios.github.io/augscript/qualification/1.0.0/public-native-consumer-darwin-arm64.json) checks ordinary downloads after publication.

[Performance](performance.md) and [safety gyms](safety-gyms.md) describe their measured scope. HTTP conformance, identity-provider hardening and unsupported targets retain the [known limits](web-library-gaps.md) and [roadmap](roadmap.md).

The [retained qualification records](./qualification/1.0.0/release-evidence.json) include host-specific conformance, performance, lifecycle and gym reports, plus the exact installed CLI and editor receipts. The tagged consumer jobs used the qualified local compiler archive before publication; the later public-install report separately checks its public download. All results describe finite checks on the recorded hosts.
