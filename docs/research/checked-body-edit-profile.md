# A checked edit for one implementation body

Implemented, unreleased profile for H05 and the LLM engineering workflow. It extends the existing standalone rename transaction; release qualification remains separate.

Accept one author-written August source unit containing the selected standalone function. Preserve its parsed header and replace only its body. Imports, other declarations, Markdown fences and changed headers are rejected explicitly. A structural frame check retains every nonselected body and declaration, including private neighbors and tests; coordinates alone are ignored. Block-style changes that alter the enclosing syntax reject, even when the candidate type-checks. The compiler supplies no business decisions, defaults or recovery code. Existing project imports provide the replacement's lookup scope.

The initial profile keeps the existing managed standalone boundary: concrete types and checked errors, with no injected or owned/borrowed public inputs, owned return, declared/effective capability effects, mutation, generics, native declaration, endpoint or interceptors. Ordinary local ownership remains governed by the checker. Check the selected contract even for private functions, then reject any other public delta caused by changed inference. A replacement can still implement the wrong behavior; checking and engineer review remain separate from independent test execution.

The command is `aug change plan-replace-body PROJECT --file FILE --symbol FUNCTION --source SOURCE_UNIT --out PLAN --json`. Planning reads a valid UTF-8 source unit of at most 1 MiB (within a regular project source file bounded to 16 MiB) and returns its exact content, resolved target, one-file edit, base/candidate revisions, checked scope and unchanged public delta. It writes only an explicitly requested, exclusively created JSON plan. Source publication uses the existing `aug change apply` journal, exclusive writer, preimage checks and recovery path.

Application regenerates the complete plan against the accepted revision, including the embedded source unit. Modified edits, scope, header, source or deltas reject before publication. Starting-project rejections retain its base revision, selected source and diagnostics separately from candidate evidence. Parse rejections refer to the supplied source unit. Checked-candidate rejections retain the exact edited source and diagnostics with that candidate revision; restored disk source is not presented as the rejected candidate. Neither planning nor publication runs tests.

Qualification covers real C/LLVM behavior, explicit checked errors, pure callback references, inferred/private contract changes, extra source units, unsupported signatures, neighboring text preservation, source/config/dependency staleness, altered plans, rollback and concurrent writer recovery. Installed JavaScript C/LLVM, type checking, 606 generated-file drift checks, the wiki build and version checks passed. The frozen suite passed 949 of 953 cases, with three optional/cold skips and the independently reproduced host LLDB launch timeout. Both scoped review axes are clear; cold/default distribution, installed editor and platform power-loss qualification remain outstanding. General body/member/project rewrites and public contract propagation are outside this first profile.
