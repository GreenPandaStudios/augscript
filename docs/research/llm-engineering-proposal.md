# Compiler context for engineering changes

Reviewed October 5, 2026 against the ergonomics candidate, following the user-supplied proposal “Optimize August for LLM coding tools in complex engineering environments.” Its 0.19.0 baseline is older than the current 0.23.0 candidate. This note records the implementation decisions; it does not turn the proposal's illustrative interfaces or estimates into shipping contracts. The [ergonomics tracker](developer-ergonomics-status.md) remains the broader accepted scope.

## Decisions

Keep compilation deterministic and independent of a model provider. Compiler facts, authored requirements, generated explanations and execution results retain different origins. A language capability never grants an assistant permission to act on the host. Existing narrow imports, labeled calls, immutable data and checked errors remain authoritative.

The useful first addition is a stronger read interface for the tools that already exist. Extend that interface through the CLI and LSP rather than adding an agent framework, another semantic index or a second prose compiler. The user has authorized implementing the proposal's suitable parts; the table distinguishes this checkpoint from later work.

No new synonymous syntax, mandatory comment quotas, global host authority calculus, implicit effectful destruction or model service is added. Existing isolated multicore workers are already implemented; the proposal's claim that threading approval remains pending is historical. GPU operations remain a separate native package.

## Protocol checks

Query facts describe the starting implementation. Returned locations and collections cannot mutate the checked program. Snapshot digests include source bytes, configuration and physical project/package metadata; a captured snapshot remains unchanged while a refreshed query observes changed metadata. File identities are relative in portable packets, including package name/version identities.

The context graph is computed before material is reduced to the output budget. A ready packet preserves all selected root contracts and implementation snippets. Dependencies and tests can be omitted, and graph uncertainty remains explicit; integrations needing complete checked facts must use `--require-complete`. Authored suites carry source and case IDs with independence `not-assessed` and execution `not-run`.

This checkpoint passes eighteen context/response regressions, 64 neighboring checks with one opt-in public-native consumer skipped, and persistent LSP/embedding parity. Native checked rename and verification run through C and LLVM. Both review axes verified the repaired inheritance, type-consumer, test-caller, foreign-boundary and response-isolation gaps. Type checking, 606 generated-document drift checks, the wiki build and installed JavaScript package gates passed. Clean default-LLVM and installed-editor gates remain outstanding for the unreleased catalog candidate.
