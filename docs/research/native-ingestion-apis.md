# Native ingestion API contracts

This contributor note records the upstream contracts used to close HTTP reception, PostgreSQL, Ed25519, and JSON compatibility gaps. It is design evidence, not a claim that every capability is implemented. Check [library gaps](../web-library-gaps.md) and the relevant regression tests for August's supported behavior.

The repository lock selects libwebsockets `5.0-stable` at `a842936f881921b6462b3328cce8e700b7a7ecd2`, GnuTLS `3.8.13`, and yyjson `0.12.0`. HTTP findings below use that exact commit; cached `server.c`, `ops-h1.c`, and `parsers.c` were compared with the pinned upstream source. The connection contracts cite libpq 17, whose cancellation API establishes a minimum client-library requirement independently of the database server version. The maintainer build selection below uses the currently supported libpq 18.6. [Dependency lock](../../scripts/native-dependencies.lock.json), [PostgreSQL 17 release notes](https://www.postgresql.org/docs/17/release-17.html#RELEASE-17-LIBPQ).

## Dispatch and admission after HTTP headers

At the pinned commit, `lws_http_action()` invokes `LWS_CALLBACK_FILTER_HTTP_CONNECTION` after parsing request headers, then invokes `LWS_CALLBACK_HTTP`, and only afterward enters the body state. The filter can inspect `lws_hdr_total_length()` and `lws_hdr_copy()`; returning nonzero closes the connection. A coroutine can therefore begin at `LWS_CALLBACK_HTTP` and wait for the body only when decoding or a handler requests it. The adapter must preserve its policy order across that wait. [Pinned server source](https://github.com/warmcat/libwebsockets/blob/a842936f881921b6462b3328cce8e700b7a7ecd2/lib/roles/http/server/server.c#L2064), [callback contracts](https://github.com/warmcat/libwebsockets/blob/a842936f881921b6462b3328cce8e700b7a7ecd2/include/libwebsockets/lws-callbacks.h#L249).

Source inspection found no automatic sender for `Expect: 100-continue` in the pinned library. It parses the Expect header token, but the server path does not send an interim response before the request callback. An adapter supporting Expect can defer `100 Continue` until admission succeeds and body consumption begins. Body data already present in the same socket read can still be delivered immediately after the header callback returns; scheduling authentication does not itself stop that callback. Bound every received chunk before retaining it. Qualify both a withheld body and headers plus body in one write. [Pinned header parser](https://github.com/warmcat/libwebsockets/blob/a842936f881921b6462b3328cce8e700b7a7ecd2/lib/roles/http/parsers.c), [HTTP/1 receive path](https://github.com/warmcat/libwebsockets/blob/a842936f881921b6462b3328cce8e700b7a7ecd2/lib/roles/h1/ops-h1.c#L90).

`lws_rx_flow_control(wsi, 0)` suppresses further read service for HTTP/1; `1` resumes it. `LWS_RXFLOW_REASON_FLAG_PROCESS_NOW` applies changes made outside that wsi's callback immediately. However, the implementation returns without applying flow control for HTTP/2, multiplexed substreams, and HTTP/2 encapsulation. `lws_h2_update_peer_txcredit()` and `LCCSCF_H2_MANUAL_RXFLOW` document a client mechanism; they do not establish a supported server backpressure contract. HTTP/2 and HTTP/3 need separately qualified receive bounds and stream termination behavior. [Pinned flow-control implementation](https://github.com/warmcat/libwebsockets/blob/a842936f881921b6462b3328cce8e700b7a7ecd2/lib/core-net/wsi.c#L391), [public receive-flow API](https://github.com/warmcat/libwebsockets/blob/a842936f881921b6462b3328cce8e700b7a7ecd2/include/libwebsockets/lws-misc.h#L1157), [HTTP/2 credit API](https://github.com/warmcat/libwebsockets/blob/a842936f881921b6462b3328cce8e700b7a7ecd2/include/libwebsockets/lws-http.h#L1250).

## Reception deadlines and cleanup

`timeout_secs_ah_idle` supplies the timeout while the connection holds the header allocation; zero selects ten seconds. Header-table reset arms `PENDING_TIMEOUT_HOLDING_AH`. `PENDING_TIMEOUT_HTTP_CONTENT` is refreshed while body chunks arrive, so it measures inactivity rather than total body reception time. A slow sender can keep that timeout alive. [Header setup](https://github.com/warmcat/libwebsockets/blob/a842936f881921b6462b3328cce8e700b7a7ecd2/lib/roles/http/parsers.c#L125), [body timeout refresh](https://github.com/warmcat/libwebsockets/blob/a842936f881921b6462b3328cce8e700b7a7ecd2/lib/roles/h1/ops-h1.c#L231), [creation options](https://github.com/warmcat/libwebsockets/blob/a842936f881921b6462b3328cce8e700b7a7ecd2/include/libwebsockets/lws-context-vhost.h#L728).

An absolute deadline needs independent monotonic accounting. `lws_set_timer_usecs()` delivers `LWS_CALLBACK_TIMER` after the requested interval without being refreshed by body traffic. It is one-shot, can be canceled with `LWS_SET_TIMER_USEC_CANCEL`, and must be rearmed deliberately. The default poll loop and libuv support it. Event-loop delay can postpone delivery, so check the deadline again before accepting data or completing work. `lws_sul_schedule()` supports a separately owned timer; cancel an application's SUL before freeing its containing state. [Timer API](https://github.com/warmcat/libwebsockets/blob/a842936f881921b6462b3328cce8e700b7a7ecd2/include/libwebsockets/lws-timeout-timer.h#L137), [timer cleanup](https://github.com/warmcat/libwebsockets/blob/a842936f881921b6462b3328cce8e700b7a7ecd2/lib/core-net/wsi-timeout.c#L28).

`LWS_CALLBACK_SERVER_NEW_CLIENT_INSTANTIATED` provides an accepted wsi before a request is available; only wsi is defined and its return value is ignored. This can arm an initial header deadline, including a connection that never completes headers. Reused connections need another explicitly defined deadline after each transaction. `HTTP_BIND_PROTOCOL` and `HTTP_DROP_PROTOCOL` delimit transaction allocation; `CLOSED_HTTP` and `WSI_DESTROY` cover connection teardown. Cleanup must wake a waiting body consumer with a checked failure and detach its transport pointer before releasing buffers. [Lifecycle callback contracts](https://github.com/warmcat/libwebsockets/blob/a842936f881921b6462b3328cce8e700b7a7ecd2/include/libwebsockets/lws-callbacks.h#L210).

## Stop accepting and drain with a bound

`lws_context_deprecate(context, cb)` closes listening sockets while existing connections remain operational. Its callback reports listener closure, not completion of application requests; libuv closes sockets asynchronously. It does not impose a grace deadline or prevent a new request on an existing keep-alive connection. The adapter therefore needs an admission flag, active-request accounting, and a monotonic grace deadline, then must cancel remaining work and destroy the context. `info.pcontext` can be used to observe completed asynchronous destruction. [Deprecation implementation](https://github.com/warmcat/libwebsockets/blob/a842936f881921b6462b3328cce8e700b7a7ecd2/lib/core-net/vhost.c#L1978), [context API](https://github.com/warmcat/libwebsockets/blob/a842936f881921b6462b3328cce8e700b7a7ecd2/include/libwebsockets/lws-context-vhost.h#L1226).

The pinned Unix periodic callback sends `SIGINT` to the process when a deprecated context has no remaining descriptors. Integrating deprecation must account for that signal behavior. `lws_cancel_service()` is the documented cross-thread wakeup; its callback is serialized onto the service loop. Perform wsi mutation and destruction there. Qualify a completed response, idle keep-alive, stalled upload, and nonterminating stream during shutdown. [Unix behavior](https://github.com/warmcat/libwebsockets/blob/a842936f881921b6462b3328cce8e700b7a7ecd2/lib/plat/unix/unix-init.c#L57), [service wakeup](https://github.com/warmcat/libwebsockets/blob/a842936f881921b6462b3328cce8e700b7a7ecd2/include/libwebsockets/lws-service.h#L79).

## PostgreSQL connection ownership and bounds

libpq represents each backend session as one `PGconn`; multiple connections provide concurrent sessions. Since libpq 17 the library is always thread-safe, but two threads must never manipulate one `PGconn` concurrently. Pool limits, waiter limits, lease deadlines, and shutdown are adapter responsibilities. A transaction and its prepared statements must remain on their leased session until commit or rollback; a pool cannot implement transaction affinity by choosing another free connection for each query. [Connection API](https://www.postgresql.org/docs/17/libpq-connect.html), [thread contract](https://www.postgresql.org/docs/17/libpq-threading.html), [prepared statements](https://www.postgresql.org/docs/17/libpq-exec.html#LIBPQ-PQPREPARE).

Use `PQconnectStartParams()`/`PQconnectPoll()` for asynchronous connection establishment and refresh `PQsocket()` after polling. `connect_timeout` is ignored by the polling API, so supply an application deadline. DNS can still block unless host addresses are supplied appropriately. Set `PQsetnonblocking(conn, 1)`, send with `PQsendQueryParams()` or `PQsendQueryPrepared()`, drive `PQflush()` with readable and writable readiness, then call `PQconsumeInput()` before `PQisBusy()` and `PQgetResult()`. `PQexec()` remains blocking in nonblocking mode. Clear all results and read until NULL, including after an error. Asynchronous operation alone does not bound buffered rows or bytes. [Connection polling](https://www.postgresql.org/docs/17/libpq-connect.html#LIBPQ-PQCONNECTSTARTPARAMS), [asynchronous command API](https://www.postgresql.org/docs/17/libpq-async.html).

libpq 17 added `PQcancelCreate()`/`PQcancelStart()`/`PQcancelPoll()`/`PQcancelSocket()`/`PQcancelFinish()`. They permit nonblocking cancellation with the original encryption and host-verification requirements. Cancellation dispatch does not prove execution stopped; read the original query to completion. Bound cancellation and subsequent draining independently, discarding the connection if cleanup exceeds that bound. Older `PQcancel()` is blocking and sends unencrypted cancellation. Before pool return, check `PQtransactionStatus()`; roll back a failed or open transaction and require `PQTRANS_IDLE`, or discard the connection. [Cancellation](https://www.postgresql.org/docs/17/libpq-cancel.html), [transaction status](https://www.postgresql.org/docs/17/libpq-status.html#LIBPQ-PQTRANSACTIONSTATUS).

Copy `PQresultErrorField(result, PG_DIAG_SQLSTATE)` before `PQclear()` and keep client-side failures distinct when no SQLSTATE exists. SQLSTATE is stable and unlocalized; for example, `23505` denotes a unique violation and `57014` query cancellation. Binary parameters use `paramFormats[i] = 1` and explicit lengths; NULL is represented by a null value pointer. Use the bytea type explicitly through its parameter type or SQL cast. Binary results require `PQgetlength()` rather than C-string length. Text bytea must pass through `PQunescapeBytea()` and its output through `PQfreemem()`. Copy borrowed result bytes before clearing the result. [Result and parameter API](https://www.postgresql.org/docs/17/libpq-exec.html), [error codes](https://www.postgresql.org/docs/17/errcodes-appendix.html).

For verified database TLS, `sslmode=verify-full` checks both the certificate chain and hostname; `require` does not establish that hostname guarantee. Preserve a logical `host` for verification even if `hostaddr` avoids DNS. A runtime using GnuTLS for HTTP does not establish libpq's TLS backend, trusted roots, or deployment closure; qualify that native dependency separately. [libpq TLS](https://www.postgresql.org/docs/17/libpq-ssl.html), [host and address options](https://www.postgresql.org/docs/17/libpq-connect.html#LIBPQ-PARAMKEYWORDS).

## Ed25519 through GnuTLS and JOSE

GnuTLS 3.8.13 provides `GNUTLS_PK_EDDSA_ED25519`, `GNUTLS_ECC_CURVE_ED25519`, and `GNUTLS_SIGN_EDDSA_ED25519`. Initialize an abstract private key, generate with `gnutls_privkey_generate()` and the selected curve via `GNUTLS_CURVE_TO_BITS()`, and derive its public key with `gnutls_pubkey_import_privkey()`. Import DER SubjectPublicKeyInfo with `gnutls_pubkey_import()` and export it with `gnutls_pubkey_export2()`. Check the imported key algorithm. Sign the original message using `gnutls_privkey_sign_data2()` and verify using `gnutls_pubkey_verify_data2()`, with Ed25519 selected and zero flags. `sign_hash2()` is unsuitable for Ed25519. Release returned signatures and exported data with `gnutls_free()` and deinitialize every key on every exit. [GnuTLS abstract key API](https://www.gnutls.org/manual/html_node/Abstract-key-API.html).

Ed25519 public keys have 32 bytes and signatures 64 bytes. SPKI uses OID `1.3.101.112`, with absent algorithm parameters and the raw public key in the BIT STRING. For a JWK, `kty` is `OKP`, `crv` is `Ed25519`, and `x` is the base64url encoding of those raw public bytes. The JOSE algorithm is `EdDSA`; the signed message is the original JWS Signing Input. Do not prehash it or apply an ECDSA DER-signature conversion. GnuTLS raw import can use `gnutls_pubkey_import_ecc_raw()` with Ed25519, raw x, and NULL y. Reject incompatible algorithm/key combinations before signature verification. [RFC 8032](https://www.rfc-editor.org/rfc/rfc8032.html#section-5.1), [RFC 8410](https://www.rfc-editor.org/rfc/rfc8410.html#section-3), [RFC 8037](https://www.rfc-editor.org/rfc/rfc8037.html#section-3.1), [raw key API](https://www.gnutls.org/manual/html_node/Abstract-key-API.html#gnutls_005fpubkey_005fimport_005fecc_005fraw).

## yyjson compatibility is an adapter contract

yyjson 0.12.0 accepts duplicate object members and retains their input order. `yyjson_obj_getn()` scans from the first member and returns the first match. A last-key compatibility mode must instead iterate members in order and replace each earlier value using its decoded, length-aware key. A strict duplicate-rejection mode can check before inserting. Test escaped-equivalent keys and keys containing an embedded NUL. [Pinned README](https://github.com/ibireme/yyjson/tree/0.12.0#limitations), [pinned lookup implementation](https://github.com/ibireme/yyjson/blob/0.12.0/src/yyjson.h#L5488).

`YYJSON_READ_NUMBER_AS_RAW` preserves every number token as `YYJSON_TYPE_RAW`; `yyjson_get_raw()` and `yyjson_get_len()` expose its bytes. `YYJSON_READ_BIGNUM_AS_RAW` covers integers outside both int64 and uint64 and floating values outside finite double; it does not preserve every number needing exact decimal handling. Choose the all-number flag when conversion policy depends on the original spelling, then implement checked int64/finite-double conversion explicitly. Keep compatibility parsing distinct from typed decoding. [Pinned read flags](https://github.com/ibireme/yyjson/blob/0.12.0/src/yyjson.h#L757), [raw-number API](https://github.com/ibireme/yyjson/blob/0.12.0/doc/API.md#yyjson_read_number_as_raw).

The parser supports nesting without a fixed application depth limit, and its public read options do not supply one. Some copy/equality helpers recurse. August must therefore enforce its own documented maximum before recursive conversion or helper use. A post-parse depth check protects conversion, while an input-size or allocator bound protects the preceding DOM allocation. Maintain one explicit root-depth convention and qualify values at the boundary and one level beyond it. [Pinned features](https://github.com/ibireme/yyjson/tree/0.12.0#features), [recursive helper contracts](https://github.com/ibireme/yyjson/blob/0.12.0/src/yyjson.h#L1861).

### Isolated build recipe

The following recipe is derived from upstream build targets and has not been executed as part of this research. It assumes verified archives extracted into separate source directories, a fresh build directory per target, and absolute paths in `openssl_source`, `postgres_source`, `tls_prefix`, `pg_prefix`, and `pg_build`. Maintainer tools include a C99 compiler, GNU make 3.81+, Flex, Bison 2.3+, Perl 5.14+, and archive tools. OpenSSL additionally needs Perl's `Text::Template` module; its distribution includes a fallback. These are maintainer dependencies, and no preinstalled `pg_config` is needed. [PostgreSQL requirements](https://www.postgresql.org/docs/18/install-requirements.html), [OpenSSL installation](https://github.com/openssl/openssl/blob/openssl-3.5.9/INSTALL.md#prerequisites), [Perl fallback](https://github.com/openssl/openssl/blob/openssl-3.5.9/NOTES-PERL.md#notes-on-perl).

| August target | OpenSSL Configure target | Build environment |
| --- | --- | --- |
| macOS 14+ arm64 | `darwin64-arm64` | Apple arm64 SDK/toolchain; deployment target 14.0 for every dependency and the final adapter |
| GNU/Linux glibc 2.36+ arm64 | `linux-aarch64` | arm64 Debian 12 build image pinned by digest |
| GNU/Linux glibc 2.36+ x64 | `linux-x86_64` | amd64 Debian 12 build image pinned by digest |

OpenSSL defines these targets; `darwin64-arm64-cc` remains a historical alias. Debian 12 supplies glibc 2.36 for both Linux architectures. Build each target inside its matching environment; merely selecting an OpenSSL target is insufficient to create a cross toolchain. Pin the container image digest and record installed tool versions or a package snapshot because mutable image tags and package repositories are not reproducible inputs. [OpenSSL target definitions](https://github.com/openssl/openssl/blob/openssl-3.5.9/Configurations/10-main.conf), [Debian 12 libc6](https://packages.debian.org/bookworm/libc6), [Docker digest guidance](https://docs.docker.com/build/building/best-practices/#pin-base-image-versions).

Set `target_cflags` to `-O2 -fPIC` on Linux and `-O2 -fPIC -mmacosx-version-min=14.0` on macOS. Set `target_ldflags` to empty on Linux and `-mmacosx-version-min=14.0` on macOS; also export `MACOSX_DEPLOYMENT_TARGET=14.0` there. Keep build prefixes outside the public package. The OpenSSL source tree must be fresh for each target.

```sh
cd "$openssl_source"
./Configure "$openssl_target" no-shared no-pinshared no-dso no-module no-zlib \
  --prefix="$tls_prefix" --openssldir="$tls_prefix/ssl" --libdir=lib \
  CFLAGS="$target_cflags" LDFLAGS="$target_ldflags"
make -j"$jobs"
make install_dev

mkdir -p "$pg_build"
cd "$pg_build"
CFLAGS="$target_cflags" LDFLAGS="$target_ldflags" \
  "$postgres_source/configure" --prefix="$pg_prefix" --with-ssl=openssl \
  --with-includes="$tls_prefix/include" --with-libraries="$tls_prefix/lib" \
  --without-icu --without-readline --without-zlib \
  --without-gssapi --without-ldap --without-libcurl \
  --without-libxml --without-libxslt --without-lz4 --without-zstd --disable-nls
make -j"$jobs" -C src/interfaces/libpq all
make -C src/interfaces/libpq install
make -C src/include install
make -C src/common install
make -C src/port install
```

`no-shared` builds static OpenSSL libraries; `no-pinshared` prevents OpenSSL from pinning a shared adapter that embeds them. `no-dso`/`no-module` remove external module loading; the default and base providers remain built into libcrypto. `install_dev` installs headers, static archives, and pkg-config metadata. Keep thread support enabled. PostgreSQL's narrow libpq target generates required headers and builds common/port support archives, without building a PostgreSQL server executable. Its `all` target also builds a shared libpq for checks and staging; an archive-only build can use `all-static-lib`, but its install target still builds `all`. [OpenSSL options](https://github.com/openssl/openssl/blob/openssl-3.5.9/INSTALL.md#no-pinshared), [provider build source](https://github.com/openssl/openssl/blob/openssl-3.5.9/providers/build.info#L72), [OpenSSL install target](https://github.com/openssl/openssl/blob/openssl-3.5.9/Configurations/unix-Makefile.tmpl#L752), [PostgreSQL prerequisite targets](https://github.com/postgres/postgres/blob/REL_18_6/src/Makefile.global.in#L393), [archive targets](https://github.com/postgres/postgres/blob/REL_18_6/src/Makefile.shlib#L232).

### Static closure and package qualification

`libpq.a` contains libpq objects rather than an embedded dependency closure. A shared adapter should link its objects, `libpq.a`, `libpgcommon_shlib.a`, `libpgport_shlib.a`, `libssl.a`, and `libcrypto.a`, followed by the configured platform libraries. Use PostgreSQL's `_shlib` support archives: they are PIC and avoid frontend helpers that exit on allocation failure. All static inputs must be built for the target and suitable for a shared library. The ordinary `pkg-config --static --libs libpq` metadata names `pgcommon`/`pgport` without `_shlib`; inspect it for platform flags, then choose the shared-library variants deliberately. [libpq link requirements](https://github.com/postgres/postgres/blob/REL_18_6/src/interfaces/libpq/Makefile#L81), [common archive contract](https://github.com/postgres/postgres/blob/REL_18_6/src/common/Makefile#L1), [pkg-config generation](https://github.com/postgres/postgres/blob/REL_18_6/src/Makefile.shlib#L341).

The proposed package embeds those dependency archives into its adapter and exposes only its intended C ABI. Qualification must inspect actual shared-library imports, macOS deployment commands, and Linux GLIBC symbol versions, then exercise relocated public imports, SCRAM authentication, verified TLS, nonblocking cancellation, and clean pool reuse on each target. A static dependency closure still uses the platform's system libraries. Do not infer the glibc floor or relocation support from configure flags alone.

A relocatable adapter also needs a documented trust-root choice. OpenSSL's compiled configuration and certificate defaults can point at the maintainer prefix; libpq accepts an explicit `sslrootcert` PEM path and `sslmode=verify-full`. Treat that as an application configuration contract and qualify it after moving the bundle. PostgreSQL 18's `PQinitOpenSSL()` and `PQinitSSL()` are deprecated no-ops; preserve the one-thread-at-a-time `PGconn` contract without adding obsolete TLS initialization. [libpq TLS and configuration](https://www.postgresql.org/docs/18/libpq-ssl.html), [OpenSSL prefix options](https://github.com/openssl/openssl/blob/openssl-3.5.9/INSTALL.md#openssldir).

Retain PostgreSQL's `COPYRIGHT`, OpenSSL's Apache 2.0 `LICENSE.txt`, applicable upstream notices, and the source/dependency pins in distribution provenance. Preserve additional notices attached to incorporated source files when assembling third-party notices. [PostgreSQL license](https://www.postgresql.org/about/licence/), [OpenSSL license](https://github.com/openssl/openssl/blob/openssl-3.5.9/LICENSE.txt).
