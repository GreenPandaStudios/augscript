# Checked project comparison

October 5, 2026. This is the next unreleased H03 profile and the change-impact part of the LLM engineering proposal. The local profile is implemented and qualified by the scoped checks below; cold default distribution and installed editor qualification remain open.

Add `aug compare BEFORE AFTER [--json]` for two local, already-installed application or library directories. Reuse whole-project checking (including authored tests), semantic graph revisions, resolved public-contract projection and exact contract differences. The command reads source; it does not fetch dependencies, run code, modify files or decide whether a change is acceptable.

The report keeps three observations separate: a declaration's checked contract changed, its source bytes (including interceptor annotations) changed, and its visibility changed. A source-byte change includes comments and formatting; it is not a claim that execution differs. Match declarations by their existing compiler identities. Added and removed identities remain separate, including a move or rename; do not infer correspondence. Retain local private declarations for impact analysis without presenting their storage or implementation references as public contracts.

For each changed declaration, return known transitive consumers before and after the change. Use resolved call, callback, type/member occurrence, inheritance, injection, applied interceptor and export relationships. Keep source locations and the relation responsible for each inclusion. Startup and test code can be consumers without being declarations. Declarations or statements not connected by checked relationships are not invented callers. Interface dispatch, native implementations, interceptor delegation and unknown external consumers stay explicit boundaries. Available test code is author-supplied material, not independent evidence or a passing result.

Both snapshots carry compiler/schema identity, checked scope, source/configuration/dependency hashes and the semantic revision. A rejected snapshot returns its exact diagnostics and revision, and comparison does not claim acceptance. A configuration or dependency change remains visible even if no declaration text changed. The initial command compares local snapshots only; it does not claim Git/remote correspondence, source-move support or an LSP snapshot-exchange protocol.

Acceptance requires independent CLI cases for unchanged projects in different directories, implementation-only changes, exact nominal type/effect deltas, transitive callers and type consumers, private helpers, startup/tests, visibility removal, additions/removals, metadata-only changes, rejected sources and unknown native/dynamic boundaries. Ordinary compiler-tested source remains the fixture; generated prose does not supply the oracle. Installed JavaScript packages must expose the same command without TypeScript stripping. Documentation and both review axes are part of the gate.

Qualification: 67 focused regressions and 28 final comparison/context cases pass. Independent reviewers verified annotation source and budget coverage, interceptor consumers, unchanged constructor/member collisions, incomplete rejections and shared package projections. Type checking, documentation generation/drift (606 files), site, archives and installed C/LLVM package consumers pass. Full-suite results are 934 passed, three optional/cold checks skipped and one source-debugger host timeout among 938 cases. This remains unreleased; no model-productivity experiment was run.
