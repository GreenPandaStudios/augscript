# Research: structured execution ergonomics

Reviewed October 5, 2026. This contributor note recommends a bounded first profile for accepted catalog items [C07 and C08](developer-ergonomics.md). The pure `RetryPolicy` record, `retryDelay` helper and bounded worker mapping are implemented in the unreleased candidate; timed execution APIs below remain proposed. The [status ledger](developer-ergonomics-status.md) lists C07 as partial and C08 as implemented with release qualification pending. This note supplies implementation contracts, not implementation evidence or approval for changing ownership, GC, channels, worker isolation, or native policy.

## Existing foundations and gaps

| Existing support | Consequence for these proposals |
| --- | --- |
| `scope`, cooperative `start`, `start worker`, and ordered `wait for` | Children are joined before scope exit; worker inputs and results are copied across isolated heaps. [Reference](../reference.md), [worker guide](../workers.md). |
| Checked immediate worker admission | `ConcurrencyError` can arise before a Task exists. Default limits are 1024 pending/uncollected jobs, 16 MiB per copied input, and 64 MiB total copied inputs; the pool has 1..64 threads. Worker heaps and outputs are not bounded by these limits. [Worker guide](../workers.md), [runtime](../../runtime/aug_tasks.c). |
| Cancellation checkpoints and caller-thread native probe | August work cooperates with cancellation. Foreign calls must return or implement their own cancellation protocol before resources can be released. [Native ABI](../native-abi.md), [runtime](../../runtime/aug_tasks.c). |
| `Clock.now()` and pure `Duration(milliseconds)` | Clock reads whole Unix seconds; Duration stores signed int64 milliseconds. Neither supplies a general monotonic deadline or sleep. [Clock declaration](../../src/stdlib/time/contracts.aug), [clock adapter](../../runtime/aug_time.c), [Duration](../../src/stdlib/values/durations.aug). |
| HTTP-specific monotonic deadlines | HTTP has checkpoint and transport timer integration, but that implementation is tied to HTTP jobs; it is not an ordinary execution-library timer. [HTTP runtime](../../runtime/aug_http.c). |
| Pure function values and collection `Transformation<T,U>` | Function values have a pure, non-throwing data method and stay on their creating heap. They cannot be ordinary worker arguments. [Reference](../reference.md), [collection declarations](../../src/stdlib/collections/operations.aug), [worker checker](../../src/workers.ts). |

A scheduled operation's errors are delayed until its wait or owning scope. A tracked wait includes possible unobserved sibling failures; public `Task<T>` carries no narrow error parameter, so a helper receiving it must currently handle or declare `Error`. Preserve these facts. Argument evaluation and admission errors remain immediate. [Checker](../../src/checker.ts), [task flow](../../src/ownership.ts), [task runtime](../../runtime/aug_tasks.c).

## C07: deadlines, bounded retry policy, and concrete sessions

Recommend an optional `august.execution` package, using existing Duration values. The following signatures describe contracts, not syntax already accepted by August.

| Proposed operation | Initial contract |
| --- | --- |
| `MonotonicClock.nowMilliseconds()` | Explicit `uses MonotonicClock.read`; checked `TimeError`. Return nondecreasing process-local int64 ticks with an unspecified epoch. Do not format or persist them as UTC. |
| `sleep(resolve Timer timer, Duration delay)` | Explicit `uses Timer.wait`; `ConversionError` for values outside 0..604800000 ms, and `TimeError` for clock/timer failures. Zero reaches a cancellation/scheduling checkpoint. Positive waits suspend the cooperative task and allow its siblings to run. Main and worker waits drive their local scheduler. |
| `awaitWithin<T>(resolve TaskAwaiter executor, Task<T> task, Duration timeout)` | Explicit `uses TaskAwaiter.wait`; require the task's creating heap and an active owning scope. Validate 0..604800000 ms; checked `Error` remains necessary for a public Task parameter, including the proposed `DeadlineError`, timer failures, operation errors, and group cleanup errors. Return T only after the selected child finishes. |
| `RetryPolicy(int maxAttempts, immutable List<Duration> delays)` | Implemented, unreleased immutable record; validate 1..64 attempts, exactly `maxAttempts - 1` delays, and each delay in 0..604800000 ms. Constructor failures are `ConversionError`. No clock, random, network, or scheduling effects. |
| `retryDelay(RetryPolicy policy, int failedAttempt)` | Implemented, unreleased and pure; attempts are numbered from one. Return the indexed delay when another attempt is allowed, null after the last attempt; invalid attempt numbers raise `ConversionError`. |

The seven-day delay ceiling and 64-attempt limit are proposed August bounds. Retry delays are caller-selected, so exponential backoff, jitter, and their overflow/random effects cannot appear implicitly. A concrete retry helper takes its actual capability inputs, catches only named retryable domain errors, ends the failed attempt's resource scope, then sleeps before the next attempt. It returns success once, preserves the final domain error, and stops on cancellation or deadline. Timer failures propagate immediately. Retain a total monotonic budget across attempts; refuse a delay that would consume the remaining budget, rather than resetting the timeout each time. Pure policy helpers can ship before timed execution; they do not by themselves complete C07.

Do not give a generic `RetryOperation<T>` a pure or incomplete `uses` contract and call capability-dependent implementations through it. An implementation must satisfy its interface's effect upper bound. Current function-value syntax also excludes checked failures and effects. Start with concrete helpers such as a file-loading retry adapter that explicitly names `FileReader.read`, `MonotonicClock.read`, and `Timer.wait`; publish additional adapters with their own operation and cleanup error sets. [Effect rules](../reference.md), [effect regressions](../../tests/effect-inference.test.mjs), [function-value checks](../../src/function-values.ts).

Retry eligibility belongs to the operation adapter: classify a documented transient error, and require an application-level idempotency rule before repeating an externally visible mutation. A boolean policy field is not proof that an operation is idempotent. For HTTP specifically, RFC 9110 distinguishes idempotent methods and restricts automatic repetition of non-idempotent requests unless their semantics or non-application are known. [HTTP idempotency](https://www.rfc-editor.org/rfc/rfc9110.html#section-9.2.2).

Resource sessions should be concrete owned resources with explicit methods such as `commit()` and `rollback()`, each declaring its real capability and checked errors. Construct/acquire them inside the executing task or worker, and return copied data after their scope joins. `drop()` performs local, non-throwing release; it cannot conceal a checked network rollback, commit, or retry. An adapter needing rollback on abandonment must perform it in an explicit method or `always` path and discard an unusable resource before local release. Preserve the primary pending failure during cancellation cleanup. [Ownership and cleanup](../reference.md), [drop checks](../../src/checker.ts), [native release contract](../native-abi.md).

### Deadline and timer prerequisites

Use an absolute monotonic cutoff calculated with checked addition once per timed wait. Nested work takes the earlier inherited cutoff; a child cannot extend an HTTP or parent-task deadline. POSIX defines CLOCK_MONOTONIC with an unspecified fixed origin and prohibits setting it; absolute waits measure against the selected clock. Scheduling may postpone delivery, so compare the cutoff again before accepting completion. These are clock semantics, not a promise of immediate interruption or a bound on cleanup duration. [POSIX clocks](https://pubs.opengroup.org/onlinepubs/9799919799/functions/clock_getres.html), [absolute sleep](https://pubs.opengroup.org/onlinepubs/9799919799/functions/clock_nanosleep.html). Deadline inheritance and explicit timer release also have a primary-source precedent in [Go WithDeadline](https://pkg.go.dev/context#WithDeadline).

The runtime needs a timer queue per scheduler/heap, rooted waiters, cancellation removal, and scheduler waits bounded by the next timer. A plain ABI 1 foreign `nanosleep` call blocks the cooperative thread and cannot implement this contract. ABI 1 excludes callbacks and August Task/object representations; general sleep and timed await therefore need reviewed internal runtime intrinsics, not a native package that retains Task pointers. Compose timer polling with the current HTTP and worker checkpoint hooks instead of overwriting them. [ABI limits](../native-abi.md), [scheduler declarations](../../runtime/aug_runtime.h), [scheduler implementation](../../runtime/aug_tasks.c).

Current worker waiting uses a short CLOCK_REALTIME condition timeout. Replace/abstract that wait for deadline work: POSIX `pthread_cond_clockwait` supports CLOCK_MONOTONIC, whereas ordinary `pthread_cond_timedwait` uses the condition's configured clock, defaulting to CLOCK_REALTIME. Recheck predicates after every wake, including timeout races. Apple's header separately declares `pthread_cond_timedwait_relative_np`; qualify a Darwin adapter rather than assuming every POSIX Issue 8 function exists on supported targets. Recompute remaining monotonic time after relative wakes. [POSIX condition waits](https://pubs.opengroup.org/onlinepubs/9799919799/functions/pthread_cond_clockwait.html), [Apple declaration](https://github.com/apple-oss-distributions/libpthread/blob/main/include/pthread/pthread.h).

On expiry, record DeadlineError as the timed child's pending cause, request cancellation, and join it; this failure uses the existing sibling-cancellation rule. A caller wanting independent timed operations creates separate inner scopes. A completed result already visible when timed await begins wins, even with a zero timeout. Otherwise completion must be accepted before the cutoff; expiry wins the tie. The controller must preserve that decision when later importing a worker's result/error instead of replacing it with successful data. An earlier operation failure stays primary. Child/group cleanup still runs; a parent failure already propagating stays primary. Detach timers and completion registrations before freeing their state, on every success, failure, cancellation, and scope exit. Go's cancellation request explicitly does not wait for work to stop, while its group Wait joins all operations; August's API must keep cancellation and joining distinct internally. [Go cancellation](https://pkg.go.dev/context#CancelFunc), [group wait](https://pkg.go.dev/golang.org/x/sync/errgroup#Group.Wait), [August join behavior](../../runtime/aug_tasks.c).

Store effective deadlines in execution/job metadata and propagate only scalar cutoff/cancellation information to workers; never share a parent controller, Task, capability, or heap object. Extend the native cancellation protocol only through an explicitly versioned/documented probe if adapters need the remaining budget; the existing read-only probe exposes cancellation alone. A blocking native adapter needs its own timeout and bounded drain/discard. Cleanup may exceed the execution budget, so timed await returns only after cleanup; abandoning live native work to meet the deadline would change the ownership contract. [Worker boundary](../workers.md), [native probe](../native-abi.md).

Track operation errors, sibling/group errors, and cancellation-cleanup errors as separate internal contributors to the effective wait/join contract. A narrow result-only task error set cannot justify suppressing the latter two. Public Task helpers retain `Error` until a reviewed type/metadata design represents all contributors. Keep immediate scheduling errors separate from these delayed failures. [Existing error flow](../../src/ownership.ts), [cleanup regressions](../../tests/concurrency.test.mjs).

## C08: real worker mapping in bounded waves

Implemented in the unreleased candidate. [The worker guide](../workers.md#map-a-list-in-bounded-waves) describes the shipped source API; [the regression suite](../../tests/worker-mapping.test.mjs) checks both native backends and the static boundary. Scheduling uses the same language operations as `start worker`, with no new capability or authority. The ordinary source template lives in `august.collections`; only its resolved compiler-owned identity can select the static bridge. Its tracked task list retains concrete `ConversionError`, `ConcurrencyError` and `IndexError`; public helpers accepting unknown Tasks still require `Error`. Source and public semantic facts remain canonical while both backends recheck a derived concrete chunk entry.

Recommend `mapWorkers(values, concurrency, chunkSize, transformation)` as a package operation with a narrow compiler bridge. Initial inputs are List<T>, `1 <= concurrency <= 64`, `1 <= chunkSize <= 65536`, and at most 1048576 elements. Reject policy violations before scheduling with ConversionError; admission/input-copy failures retain immediate ConcurrencyError. Empty input returns an empty list after policy validation. Concurrency bounds this map call's chunk jobs; it does not reserve pool threads or set a process-wide limit. Return one U per input in original order, without changing the input. T and U must pass the actual copied-data checker, not merely a broad Data bound. These are proposed item/job bounds; native worker heaps, result byte sizes, and total retained output still need their own application limits.

Require the `transformation` argument to be a directly named, resolved, concrete standalone function with one `value:T` input, copied U result, no injection/ownership inputs, no effects, no checked errors, and no task starts in its reachable code. Match the existing pure Transformation contract, but specialize that declaration at the map call: generate a standalone chunk entry which directly calls the selected function. Transfer only chunk data; do not materialize or copy a behavior object. Reject closures, stored function values, interface implementations, unresolved targets, and generic function references in this first profile. This restriction needs an explicit diagnostic and semantic facts; current ordinary `transform` does not provide the bridge. Apply the complete worker reachability/native-workerSafe checks to the generated entry. [Function values](../reference.md), [worker checker](../../src/workers.ts), [task lowering](../../src/ir.ts).

The package divides contiguous inputs into chunks, enters one inner scope, starts up to concurrency actual worker jobs, waits for the complete ordered Task list, joins/releases that scope, and appends results in chunk order. Repeat for the next wave. Every transformation runs once on successful completion; concurrency one still uses a worker. This is real scheduling with a barrier between waves. It requires no public channels or wait-any primitive. A wave's slowest job delays the next wave; that is an explicit first-profile tradeoff.

Each wave bounds unfinished jobs and scope-rooted completed Task/input/output graphs. A single scope spanning a rolling window would retain completed Tasks until scope exit in the current runtime, even after their wait. A later refill scheduler needs reviewed completion selection and safe removal of observed child roots; it cannot be claimed from `Task<T>` today. Python distinguishes chunk size from its submitted-result buffer bound, and Go's group limit bounds active operations; August likewise needs separate chunk and concurrency contracts. [Task rooting/join](../../runtime/aug_tasks.c), [Python map](https://docs.python.org/3/library/concurrent.futures.html#concurrent.futures.Executor.map), [Go SetLimit](https://pkg.go.dev/golang.org/x/sync/errgroup#Group.SetLimit).

If admission fails midway through a wave, preserve that immediate failure, cancel/join already scheduled children, and return no partial list. Existing external pool limits can still reject concurrency values within the API limit; do not retry admission or raise global limits implicitly. Parent cancellation stops new waves and joins the current wave. The map's first profile admits only pure entries, so it grants no child file/network authority. If scheduling receives a named capability such as WorkerPool.map, expose that effect; do not infer permission to call unrelated worker-local services. Effectful or throwing mapping requires a separate profile with explicit capabilities and the complete operation/group/cleanup error union.

## Required evidence and remaining decisions

Before timed execution moves out of partial, and before either implementation passes release qualification, retain meaningful tests on C and LLVM lowering and the supported native targets. For timers, use an injected deterministic monotonic clock/timer driver to test negative/zero/max/overflow inputs, backward wall-clock changes, nested earlier cutoffs, expiry/completion ties, and disarming every exit. Native tests must exercise a sleeping sibling making progress, cancellation while parked, worker completion during a timer wake, native probe cancellation, and timer state released without a late callback. Test operation failure, sibling failure, and cancellation-cleanup failure as separate checked-error contributors, including preservation of an already propagating parent error. Existing [worker admission](../../tests/native/worker-admission.c), [completion race](../../tests/native/worker-wait.c), [task cleanup](../../tests/concurrency.test.mjs), and [worker regressions](../../tests/workers.test.mjs) provide concrete starting points.

For mapping, an instrumented worker entry must show actual OS-thread execution and a peak no greater than the requested concurrency. Force reverse completion order and verify ordered results; cover empty input, partial final chunks, one-thread nested-worker progress, source mutation after capture, copied alias graphs, and admission failure after some submissions. Verify cancellation joins resources and prevents another wave. Negative compiler cases must reject behavior/capability/Task/native-handle captures, impure or throwing transformations, and native calls without workerSafe. Pure retry tests verify exact delay lookup, the final attempt, and no hidden calls; concrete adapter tests verify bounded attempts, total budget, nonretryable failure, resource release between attempts, and final error identity.

Pure retry records/helpers are implemented in ordinary August; they add no scheduling or clock behavior. Concrete resource adapters are feasible against their declared capabilities. General cancellable timers and timed await require runtime integration; reusable worker mapping now uses the restricted static specialization bridge. Remaining timed-execution decisions are its public capability names, deadline tie/error representation and how native adapters obtain an inherited remaining budget. These must be recorded before implementation. Keep C07 partial until timed execution is implemented and qualified. C08 remains unreleased until platform and distribution qualification passes.
